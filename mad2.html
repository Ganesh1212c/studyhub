Review & Roadmap

🔁Review of MAD-I

02

What is an app (at least in our context):

  • An application or program used for interacting with a computing system
  • Allow the user to perform some tasks useful to them

Components:

  • Backend: Store data, processing logic, relation between data elements etc.
  • Frontend: User-facing views, abstract for machine interaction
  • Naturally implies a client-server or request-response type of architecture

Why Web:

  • Close to universal platform with clear client-server architecture
  • Low barrier to entry - trivial to implement simple pages and interaction
  • High degree of flexibility - possible to implement highly complex systems
In simple words

An app is a tool on a computer that helps you do something useful, like ordering food or checking your marks.

Every app has two halves that talk to each other:

  • Frontend: the part you see and touch (pages, buttons, forms).
  • Backend: the hidden part that stores data and decides what to do with it.

They talk in a simple pattern: the frontend asks (a request) and the backend answers (a response). This is called a client-server design.

Why the web? Every phone and laptop already has a browser. A simple page takes only a few lines to write. And the same idea can grow into very large systems.

Think of it like this: a restaurant. The menu and the waiter are the frontend. The kitchen is the backend. You never enter the kitchen; you send an order and food comes back.

🧱Review of the Web Application Development Model

03

Presentation

HTML for semantic content, CSS for styling

Logic

Backend logic highly flexible - we used Python with Flask

Application architecture:

  • Model - View - Controller. Good compromise between understandability and flexibility

System architecture:

  • REST principles + sessions - how to build stateful applications over stateless protocols
  • APIs: separate data from view
  • RESTful? APIs - useful for basic understanding, but not strict adherence to REST

Others:

  • Security, Validation, Logins and RBAC, database and frontend choices etc.
In simple words

A web app is built from a few kinds of work:

  • Presentation: HyperText Markup Language (HTML) says what is on the page (heading, button, list). Cascading Style Sheets (CSS) says how it looks (colours, spacing).
  • Logic: the backend code that decides what happens. We used Python with a tool called Flask.
  • Model - View - Controller: split the app into three jobs. The model holds data and rules. The view is what the user sees. The controller receives a request, asks the model, and picks the view.

System architecture is about how the pieces talk. Web servers do not remember you between requests (this is called stateless). To make apps feel continuous we use sessions: the browser keeps a small ID, and the server uses it to recognise you again. That is how you stay logged in.

Representational State Transfer (REST) is a set of design ideas for doing this neatly. An Application Programming Interface (API) sends only data, not whole pages, so the frontend can show it any way it likes. "RESTful?" with a question mark means we followed the ideas loosely, not perfectly.

Others: real apps also need security, validation (checking what users type), and logins with Role-Based Access Control (a student and an admin are allowed to do different things).

Think of it like this: a theatre. The controller is the stage manager, the model is the script, and the view is what the audience sees.

JavaScript is the programming language of the web browser. This world answers four questions:

🕰️Origins

06
  • Originally created in 1995 as scripting language for Netscape Navigator
  • Intended as “glue” language
    • Stick modules from other languages together
    • Not really meant for much code
  • Primarily meant to assist “applets” in Java - hence JavaScript
    • Trademark issues, name changes, …
  • Issues:
    • Slow
    • Limited capability
In simple words

JavaScript was born in 1995 inside the Netscape Navigator browser. It was made quickly as a small glue language: short scripts that connect pieces written in other languages.

Its name comes from Java, a very popular language at the time. Java programs called applets (small programs inside a web page) ran in browsers, and JavaScript was meant to help them. They are two different languages, though.

Early JavaScript was slow and could only do limited things, so nobody expected much code to be written in it.

Think of it like this: glue in a craft box. It is not the main material; it just holds the other pieces together.

⚡Power

07
  • Glue was useful, but…
  • Then Google Maps, Google Suggest etc. (~ 2005)
    • Pan around map, zoom in/out seamlessly - fluid user interface:
    • Load only what is needed!
  • Described and Named Ajax - Garrett 2005
    • Asynchronous Javascript and XML
  • Allowed true “web applications” that behave like desktop applications
  • Evolved considerably since then
    • Much more on this approach moving forward
In simple words

Around 2005, Google Maps and Google Suggest showed something new. You could drag and zoom a map, or see suggestions while you typed, without the whole page reloading.

The trick: JavaScript quietly asks the server for just the small piece it needs, in the background, and updates only that part of the page. Jesse James Garrett named this Ajax (Asynchronous JavaScript and XML) in 2005.

Asynchronous means the page does not freeze while it waits. Extensible Markup Language (XML) was the data format back then. Today most apps use a lighter format called JavaScript Object Notation (JSON), but the idea is the same.

The result: websites started to feel like desktop apps.

📜Standardization

08
  • Move beyond Netscape needed
  • ECMA (European Computer Manufacturers Association) - standard 262
  • Subsequently called ECMAScript
    • Avoid trademark issues with Java
  • In practice:
    • Language standard called ECMAScript (versions)
    • Implementation and use: JavaScript
  • Significant changes in ES6 - 2015
    • Yearly releases since then
    • “Feature readiness” oriented approach
In simple words

If every browser maker invents its own version of a language, the same page behaves differently everywhere. So the language needed a shared rule book.

  • ECMA (European Computer Manufacturers Association) is a standards organisation. Its rule book number 262 is called ECMAScript. They avoided the name JavaScript because of trademark issues with Java.
  • ECMAScript is the rule book. JavaScript is what you actually use. Like a recipe (the rule book) and the dish (the real thing).
  • ES6 (ECMAScript 2015) was a big upgrade. It added classes, modules, let, const and arrow functions. Since then there is one smaller update every year.
  • Feature readiness means a new feature is added as soon as it is ready, instead of waiting for one giant release.

🧭What version to use?

09
  • ES6 has most features of modern languages (modules, scoping, class etc.)
  • Some older browsers may not support all of this

Possible approaches:

  • Ignore old browsers and ask user to upgrade
  • Package browser along with application - useful for limited cases, like VSCode (Electron apps)
  • Polyfills: include libraries that emulate newer functionality for older browsers
  • Compilers: BabelJS - convert new code to older compatible versions

Backend

  • Node.js, Deno: directly use JS as a scripting language like Python
In simple words

Newer JavaScript has better features, but older browsers may not understand them. You have four choices:

  • Ignore old browsers: ask users to upgrade.
  • Ship your own browser with the app. VSCode does this using Electron, so it always knows which browser version it has.
  • Polyfill: a helper script that adds a missing feature to an old browser. Like a patch.
  • Compiler (BabelJS): translates new code into older code. Like translating modern English into older English.

On the backend, Node.js and Deno let you run JavaScript outside the browser, just like running a Python script.

🧬Implications of JS Origins

10

Ease of use given priority over performance (to start with)

Highly tolerant of errors - fail silently

  • Debugging difficult!
  • Strict mode: "use strict";

Ambiguous syntax variants

  • Automatic semicolon insertion
  • Object literals vs Code blocks {}
  • Function: statement or expression? Impacts parsing

Limited IO support: errors “logged” to “console”

Closely integrates with presentation layer: DOM APIs

Asynchronous processing and the Event Loop - very powerful!

In simple words

JavaScript was created fast, with the goal that beginners could use it easily. That choice explains many of its quirks:

  • Forgiving: many mistakes do not crash the program. It silently keeps going, so bugs are hard to find. Writing "use strict"; at the top turns on a stricter mode that reports more mistakes.
  • Ambiguous syntax: semicolons are optional because the language adds them for you (sometimes wrongly). The curly braces {} can mean an object or a block of code, depending on where they appear. A function can be a statement or an expression, depending on where it is written.
  • Limited input and output: the language itself has very little built in for this. The simplest way to see a message is console.log, which prints to the console, a hidden panel for developers in the browser.
  • Closely tied to the page: its main job is to change the page through the Document Object Model (DOM).
  • Asynchronous and the Event Loop: JavaScript does one thing at a time but keeps a to-do queue. When a click or a server reply arrives, it joins the queue and is handled when JavaScript is free. So waiting never freezes the page.

▶️Using JS

11
  • Not originally meant for direct scripting
    • Usually not run from command line like Python for instance
  • Need HTML file to load the JS as a script
    • Requires browser to serve the files
    • Links and script tags etc.
    • May not directly work when loaded as a file
  • NodeJS allows execution from command line

Examples here will be shown on Replit for the most part

In simple words

JavaScript needs a place to run. Usually that place is a web page in a browser.

  • Write your code in a .js file. Load it from an HTML file with a script tag. Open the HTML file in the browser.
  • Sometimes this does not work if you just double-click the file, because some browser features need the files to be served by a web server. Tools like Replit handle that for you.
  • Node.js lets you run JavaScript straight from the terminal (the command line), the way you run Python.

The course examples will mostly run on Replit, an online code editor, so you do not need to install anything.

🌳DOM

12
  • Document Object Model
    • Structure of the document shown on the browser
  • DOM can be manipulated through JS APIs
  • One of the most powerful aspects of JavaScript
  • Input: clicks, textboxes, mouseover, …
  • Output: text, colours/styles, drawing, ...
In simple words

When a browser loads a page, it turns the HTML into a tree of objects in memory. This tree is the Document Object Model (DOM). Every heading, paragraph and button is one branch.

JavaScript can read and change this tree, and the page updates instantly. This is one of JavaScript's most powerful abilities.

  • Input (what the user does): clicks, typing in text boxes, moving the mouse over something.
  • Output (what JavaScript changes): text, colours and styles, drawings.

Think of it like this: a family tree of your page. JavaScript is someone who can walk to any person in the tree and change their name or clothes.

🖥️Basic Frontend Usage

16

Frontend JavaScript: must be invoked from HTML page

  • In context of a “Document”
  • will not execute if loaded directly

Scripting language - no compilation step

Loosely structured - no specific header, body etc.

In simple words

Frontend JavaScript lives inside a web page (a "Document"). If you open a .js file on its own, nothing happens, because there is no page for it to work on.

No compilation step means you write the code and the browser runs it straight away. You do not need to build or compile first.

Loosely structured means there is no required starting point like main in some other languages. The browser just reads the file from top to bottom.

🧮Statements and Expressions

18

Expression

Piece of code that can be executed to obtain a value to be returned

Anywhere you need a “value” - function argument, math expression etc.

Statement

Piece of code that can be executed

Standalone operation or side effects

In simple words

An expression is anything that gives back a value. A statement is an instruction that does something.

  • Expressions: 10, "Hello world", 2 + 3. Each one produces a value, so you can use it anywhere a value is needed, such as inside a function call or a maths formula.
  • Statements: if, loops, and declarations. They are standalone actions, or they have side effects (they change something).

Quick test: if you can put it inside console.log( ... ), it is an expression.

🧩Data Types

19

Primitive data types:

built into the language

  • undefined
  • null
  • boolean
  • number
  • string

(+ bigint, symbol)

Objects:

Compound pieces of data

Functions

  • Can be handled like objects
  • Objects can have functions: methods
  • Functions can have objects???
In simple words

Every value has a type. There are two groups:

  • Primitive types are the simplest values built into the language: undefined (no value yet), null (deliberately empty), boolean (true or false), number, string (text), plus bigint (huge whole numbers) and symbol (a unique tag).
  • Objects are bundles of related values, such as a student with a name and marks.

Functions are special: you can handle them like any other value (store them, pass them around). An object can hold functions, and those are called methods.

Functions can have objects??? Yes. A function is itself an object, so you can attach data to it. It looks strange, but it follows from functions being objects.

🔡Strings

20
  • Source code is expected to be in Unicode
    • most engines expect UTF-16 encoding
  • String functions like length can give surprising results on non-ASCII words
  • Can have variables in other languages!
    • But best avoided… keep readability in mind
In simple words

A string is text. JavaScript code is written in Unicode, a huge character set that covers every language and emoji. Most engines store text as UTF-16, where each character takes one or two 16-bit pieces.

Because length counts those pieces, an emoji or a rare symbol can look like one character but count as two. This surprises people.

JavaScript even allows variable names in other languages, but it is best to avoid that so your code stays easy to read.

Templates (strings in backticks) let you put values inside text with ${ }.

🕳️Non-Values

21

undefined

  • Usually implies not initialized
  • Default unknown state

null

  • Explicitly set to a non-value

Very similar and may be used interchangeably in most places - Keep context in mind when using for clarity of code

In simple words
  • undefined means no value has been given yet. JavaScript uses it by default, for example for a variable that was never set.
  • null means nothing, on purpose. You set it yourself.

They are very similar and often interchangeable. Pick a meaning for each and stay consistent, so your code is clear.

Think of it like this: undefined is an empty form field that nobody has filled in yet. null is a field where someone wrote "not applicable".

⚖️Operators and Comparisons

22
  • Addition, subtraction etc.
    • Numbers, Strings
  • Coercion
    • Convert to similar type where operation is defined
    • Can lead to problems - needs care
  • Comparison:
    • Loose equality: == tries to coerce
    • Strict equality: === no coercion
  • Important for iteration, conditions
In simple words
  • Operators like +, -, * and / work on numbers. + also joins strings.
  • Coercion means JavaScript quietly converts one type into another so an operation can work. It is handy, but it can cause surprises.
  • Loose equality == converts types first, then compares. Strict equality === compares without converting.

Comparisons decide which if path runs and when a loop stops, so a wrong comparison means a wrong decision.

Habit to build: use === almost always.

📦Variables and Scoping

23
  • Any non-reserved identifier can be used as a “placeholder” or “variable”
  • Scope:
    • Should the variable be visible everywhere in all scripts or only in a specific area?
    • Namespaces and limiting scope
  • let, const are used for declaring variables
    • Unlike Python, variables MUST be declared
    • Unlike C, their type need NOT be declared
    • var was originally used for declaring variables, but has function level scope - avoid
In simple words

A variable is a labelled box that holds a value. In JavaScript you must declare it with let or const. Python lets you skip this. C also makes you write the type. JavaScript needs the keyword but not the type.

Scope is where a variable can be seen. Should it be visible everywhere, or only in one small area? A smaller scope is safer, because fewer parts of the program can change it by accident. Namespaces group related names under one label so they do not clash.

var is the old way. It only respects function boundaries, so it leaks out of blocks like if and for. Avoid it.

🔒let and const

24

const: declares an immutable object

  • Value cannot be changed once assigned
  • But only within scope

let: variable that can be updated

  • index variable in for loops
  • general variables
In simple words
  • const: the name is locked to its first value, so you cannot reassign it. The lock only holds inside the scope where it was declared.
  • let: the variable can change later. Use it for loop counters (like i) and other values that must update.

Heads up: const locks the name, not the inside of an object or list. You can still add items to a const list.

In simple words

Code normally runs from top to bottom. Control flow changes that path.

  • if / else: choose between paths.
  • for / while: repeat.
  • break: leave a loop right now. continue: skip to the next round.
  • switch: pick one of many options.

⚙️Functions

26

Reusable block of code

Can take parameters or arguments and perform computation

Functions are themselves objects that can be assigned!

In simple words

A function is a reusable block of code, like a recipe you write once and use many times.

It can take inputs (called parameters when you define it, and arguments when you call it), do some work, and give back an answer.

In JavaScript, functions are objects themselves. So you can store them in variables, pass them to other functions, and assign them like any other value.

✏️Function Notation

27
In simple words

There are three ways to write the same function:

  • Regular declaration (a statement): the oldest way. You can call it even above the line where it is written.
  • Named variable (an expression): a function stored in a variable. It only works after that line.
  • Arrow function (an expression): the shortest form. With one expression and no curly braces, the result is returned automatically.

🎭Anonymous functions and IIFEs

28

Why?

Older JS versions did not have good scoping rules.

Avoid IIFEs in modern code - poor readability

In simple words

An anonymous function has no name. You either store it in a variable or hand it straight to something else.

An Immediately Invoked Function Expression (IIFE) is an anonymous function wrapped in brackets and run on the spot.

Why did people do this? Old JavaScript had no good way to keep variables private. Wrapping code in a function created a private room, so its variables did not leak out. Today let, const and modules do that job, so IIFEs are rarely needed and are hard to read. Avoid them in new code.

In simple words

Think of it like this: a smart doorbell. It listens for someone pressing it (input), then plays a sound (output).
